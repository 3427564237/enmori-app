# ZHOU controlled chat verification packet

The packet is an explicit verification composition in
`backend/test/zhou-controlled-chat-packet.ts`; it is not ordinary runtime wiring.
It joins JIN's actual `ControlledConversationPrompt` and
`ControlledOllamaTransport`, the authorized generation wrapper, the bounded
runtime, and ZHOU's asynchronous operation executor/Application. Auth, completed
owner, complete **empty** Note inventory, canonical U/A readback, storage, and
complete-body acceptance remain handwritten synthetic Ports. No HTTP, actual
Firebase Auth/Firestore, device, nonempty Note, model, deployment or Release
acceptance is inferred from the local packet tests.

The existing Q31 decision controls model identity, complete-input limits,
60/5/45 timing, one-active/two-queued capacity, cancellation, quarantine, raw
parsing and separate semantic acceptance. The packet does not change those
requirements or select an endpoint, host value, dependency, model, tokenizer,
schema, fallback or architecture. LI remains the actual controlled Linux host
operator; JIN's private binding/counter handoff remains authoritative for host
identity and tokenizer configuration. New ZHOU source follows LI's review path.

separate full34-case policy corpus; they are not silently rewritten to this

## LI local import and required bindings

Import the compiled helper into LI's existing private operator context. It
contains no private module loader, installer, credential file, network listener,
deployment command or automatic model retry. The fixed current-message fixture
is `今天读书了。`; the Note inventory is genuinely empty **within this synthetic
fixture only**, and no production Note-authority claim is made.

```javascript
import { startControlledChatPacket } from
  "./backend/dist/test/zhou-controlled-chat-packet.js";

// binding, counter and gates come from LI's reviewed private host composition.
// They are not request fields, environment guesses, copied secrets or fake CI
// acceptance decisions. Omit http and clock for the actual existing local host
// and the existing monotonic clock implementation.
const packet = startControlledChatPacket({ binding, counter, gates });
const report = await packet.outcome;
console.log(JSON.stringify(report)); // content-free, bounded observations only
```

The independently implemented candidate gate is mandatory. The helper's absent
gate default rejects before generation; the prompt/compiler/raw parser is not a
semantic validator. An explicit gate supplied by an operator is recorded only as
`explicitly-injected`; the helper does not certify that it was the reviewed
implementation or that it was actually approved. Bind its exact source/policy
version and corpus evidence separately. Do not substitute the permissive local
test gate or use a second model for validation.

The new concrete candidate is exported from
`backend/dist/src/ai-conversation/application/bounded-conversation-semantic-policy.js`
as `boundedConversationSemanticCandidate`. Bind it as `gates.candidate` while
retaining the original pre-generation context/availability guard; complete
token measurement still occurs in JIN's real compiler. The bounded policy
allows only exact recognized routine statements with fixed attribution.
Unrecognized or ambiguous paraphrases reject the entire reply. A real model
response can therefore yield `AI_REPLY_REJECTED`; that outcome is not a
successful complete chat and must not be relabelled as one. The prompt is not
changed here, and no synthetic reply is substituted for a rejected model reply.

The matching counter must be the previously provisioned pinned tokenizer, not a
numeric/character approximation. Host/template equivalence, immutable loaded
9B identity, full returned-input-count equality and protected host isolation
retain their separate LI evidence requirements. Private identities remain in
the private operator evidence, not this report, Git or public Issues.

For a separately authorized cancellation observation, the helper exposes
`cancel()` and `disconnect()` on the original handle; they never create a new
generation. A content-free `checkpoint` can observe `model-dispatched` after
the actual fetch call has been issued. Invoke Cancel once for the intended
handle; retain the same packet and inspect `state()` afterward. The report is
a terminal-time snapshot: later confirmed completion can change `state()` but
cannot change the report or deliver late content.

**One packet owns one isolated verification runtime.** An aborted socket or
HTTP error is not remote-stop proof. A report or later state showing quarantine
requires LI to retain host unavailability until actual termination is confirmed
or the approved process supervisor restores the host. Do not construct another
packet/runtime to bypass a quarantined lane or run these packets concurrently.
No public/current-user transaction should share this isolated verification
composition. The binding's existing host authority remains mandatory.

`requests: 4` exercises bounded synthetic-owner admission against the same one
runtime; it does not prove actual Firebase per-user identity. Real calls can
finish before a timing boundary, so their measured result cannot be relabelled
as actual45s/60s timeout evidence. The deterministic CI timing cases and an
actual controlled-host cancellation/latency/failure run are separate evidence.
The operator must record which actual boundary was reached, exact source,
policy version, timestamp and latency; no timing limits are modified.

## Remaining acceptance boundaries

Actual host execution is **Not Run here**. Successful real model generation,
actual full-input counts, actual semantic acceptance, real Auth/store/readback,
native template equivalence, controlled host cancellation/termination evidence,
mobile/backend/device journey, nonempty Note producer guarantees and peer
disposition remain separate. The synthetic retention marker represents the
fixture's user/assistant commits, not an actual Firestore
`lastPersistedMessageAt` verification. `localContentHoldersCleared` concerns only
observable holders owned by the helper; it does not claim destruction of an
external counter/gate/HTTP supplier's private heap or pending SDK bytes.
