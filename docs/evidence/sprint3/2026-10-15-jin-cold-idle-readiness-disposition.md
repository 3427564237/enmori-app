## Meaning of current signals

| Signal on #117 | What it establishes | What it does not establish |
| --- | --- | --- |
| HTTP listening, phase running, accepting true | Foreground service/admission is running | The model is loaded, an AI response will pass, or every dependency is healthy |
| hostPreflightPassed / tokenizerReadinessPassed | Startup checks completed on this operator | A fresh host observation at the time the status file is read |
| adapterState ready/stopped | Last adapter lifecycle transition | Continuous observation or a residency lease; it remains unchanged while the host idles without another adapter call |
| modelPending0, no hold | Those exposed counters show no tracked pending model/hold at that checkpoint | Loaded model, complete proof from missing/stale receipts, or permission to replace an uncertain original |
| modelAttempts | Number of service calls entering the adapter's generate method | Number of actual `/api/generate` POSTs; a preflight failure can increment this counter without content generation |
| Exact-model `/api/ps` context8192 observed now | Point-in-time residency observation using the bound model identity | Future residency or an atomic reservation through dispatch |

## Existing-scope LI operator procedure

1. Treat stale/missing status or an absent model as unknown/unavailable for the next AI action. Pause only the run-owned phone app when necessary to prevent concurrent Send. Keep the original foreground Backend, owner/data and applicable Auth/HTTPS mappings. Do not call service stop as a warming mechanism: stop initiates owned-data cleanup.
2. Establish the original is actually quiet using the existing operator/runtime receipts: no pending original model/compiler/operation, quarantine or hold. Resolve inconsistent/missing evidence before acting. HTTP health, no current socket or a terminal client alone does not prove settlement. If unresolved, preserve the original and report the specific hold to LI; no preload/new process/reset bypass.
3. Using LI's existing private pinned host binding, perform the existing read-only version/tag/loaded-model checks. Match the exact bound identity/digest and context8192 privately; do not print credentials/digests/raw content into public evidence. If absent and the original is quiet, LI may reuse its **already authorized manual** empty-prompt/num_predict0 preload procedure, unchanged. This packet does not supply a warm loop, new keep_alive value, residency duration, host-global setting or alternate model. Preserve any failure/unknown result rather than automatic retry.
4. Require that manual preload's own confirmed completion and zero generated tokens, then take a fresh read-only exact-model/context observation. Record when and by whom the observation was made; absence or malformed evidence remains unavailable. The manual action must not create an AI conversation/message or change stored user state. Compare service counters against their prior baseline; existing history need not have modelAttempts0, and attempts are not a POST counter.
5. Reconnect through the existing private fresh handoff/installed-package verification to the **same original** service and owner, without resetting data or reinstalling as a repair. LI's owned app may be resumed/reconnected; this does not restart the Backend. The next user Send still performs its own checks and may fail closed after another idle unload. Do not promise a permanent ready window or create a fabricated result to hide that failure.
6. If the previous Send might already have saved U or has unknown effects, first use the approved outcome/readback and original-ID retry protections. Manual warming/reconnection is not request cancellation, no_effect or retry authorization. Do not extend60/5/45, original expiry or cleanup clocks.
7. When LI actually ends the session, use the existing explicit service stop and all three cleanup receipts/profiles/ports checks; remove only owned private files/mappings afterward. Active preview lifetime and completed test-session cleanup remain separate.

No new key/deployment/PM product selection is needed to reuse this existing authorized manual procedure. LI alone operates its current host/device; JIN performed none of these actions in this packet.
