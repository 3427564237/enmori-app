## 实际通过

| 流程 | 观察与回读 |
| --- | --- |
| 真实登录与初始化 | 用户完成登录、Username、同意及兴趣选择；手机进入 Home，服务端规范账号绑定和账号存在，邮箱已验证。 |
| 资料保存 | 用户在手机填写并保存 Display Name、BIO；重新加载资料可见，服务端 profileRevision=2。未公开姓名、BIO、邮箱或用户 ID。 |
| 设置保存 | 使用用户现有选项点击 Save，没有改变隐私、同意或地图分享选择；settingsRevision=1。手机显示默认签到及兴趣/位置/参与信息 Private、地图分享关闭。 |
| 正常停止及恢复 | 服务正常停止后资料 Reload 显示 “Profile could not be loaded. Try again.”；正常启动后再次 Reload 恢复已保存资料。未清空数据或重建账号。 |
| 重启后持久回读 | 保存后与重启后的整个账号、隐私投影、兴趣文档规范化摘要一致；两个 revision 不变，兴趣数量 2。只读 Admin 查询用于核对持久数据，手机 Reload 用于验证应用读取路径。 |
| 退出与返回栈 | Sign out 回到登录页；Android Back 退出应用，没有返回前一账号页面。重新打开仍为登录页。 |
| 再次登录 | 用户亲自重新登录，直接进入 Home，没有重复引导。Auth 最近登录时间推进；My profile 再次显示此前保存的姓名、BIO 与两项兴趣，三个摘要及 revision 仍与保存后相同。 |

摘要比较基准为设置保存之后，不能与保存前的隐私默认字段摘要混用。UTC 时间：保存后 `03:08:32.929Z`；重启后 `03:09:20.292Z`；重登后 `03:14:00.050Z`。均为 2026-10-20（本地 SGT +08:00）。脱敏机器结果见 [receipt.json](receipt.json)。原始回读元数据仅保存在本机私有状态目录，没有将账号正文或凭证提交到 Git。
