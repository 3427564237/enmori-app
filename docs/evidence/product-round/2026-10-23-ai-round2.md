## Delivered path and boundary

- Social shell: conversation actions → **Find in conversation**. Classic shell: search icon. The internal route inherits the current app theme/navigation motion and requires no shared route or composition change.
- Query matching is case-insensitive literal text against currently loaded, available persisted messages. It excludes tombstones, null text and local pending outgoing text. Search scope is visible; no-match never claims the unloaded transcript was searched.
- Selecting a result resolves its stable message ID against current controller state and displays it with adjacent messages. An unavailable replacement immediately removes the old text, including from an open context view.
- **Load earlier messages** alone calls existing `loadMessages(before: nextCursor)`. An accepted page advances or exhausts the cursor. A retained cursor is shown as a failed load, with query retained for explicit retry. There is no automatic pagination or network search.
- **Return to conversation** leaves the draft and selection intact. Search never calls send, retry, cancel, result recovery, conversation switching or model generation. Queries/selection are page RAM, not a saved index or copied content store.
- Pending, unknown, deletion and privacy/session states retain their existing guards. Session/conversation replacement or restrictive state permanently invalidates the open search. A late callback cannot restore it after consent is restored.

Backend confirmed the existing message API is sufficient. Pages contain at most 20 messages and use the earliest sequence as the next-before boundary. Backend still revalidates message/source availability; existing historical-read rules are not replaced by a new server-wide consent ban. Its separate bounded audit is [Draft PR #180](https://github.com/3427564237/enmori-app/pull/180), `fe1dde54a212bae4d124e6f772a8e85572d7bc39`; its isolated checks are not real-runtime evidence for this UI.
