## 推荐的首条完整流程

用户在当前话题选择一条已保存的本人消息，明确设置跟进时间和时区。
到时 Backend 重新核对来源、同意、话题有效期和频率，再经本地模型生成。
它以真正的 AI 主动消息保存到原话题，显示原因与可核验的来源；用户打开后
能够接着回复。模型输出本身不能创建任务、改活动意向或取得通知发送权限。

| 待选范围 | 推荐的具体边界 | 对既有规则的影响 |
| --- | --- | --- |
| F0：明确要求的稍后跟进 | 默认关闭；仅此类别；每滚动 24 小时最多一次，至少间隔 8 小时；最多 3 个待处理请求；默认确认时区的 22:00–08:00 安静时段，可暂停、取消或关闭；不自动读取签到/活动/位置 | 新增明确跟进用途、真正主动消息身份、设置/任务与投递状态/单设备注册/话题已读四类最小记录及其接口 |
| R-ANCHOR：跟进不延长旧记录寿命 | 主动消息不推进原话题的 90 天保留起点；话题过期就不再生成或复活；普通用户消息及其回复继续原规则 | 对 Q14 明确增加这一小范围例外，避免自动跟进使整段旧内容多保留 90 天 |
| F1a：当次手选自己的签到 | 单次本地回复用途；最近 7 天最多 5 条；仅当前正文、Mood/Activity 和原发生时间；临时附加/排除、发送前核对；不带天气、坐标或地点标签 | 对 19 日简化方案的额外上下文关闭规则，仅增加“本次明确选择”的例外，不开启后台或下次自动使用 |
| 本次参考与正确跳转 | Backend 给出最少来源卡片与受权跳转；旧来源改变/删除/权限不明就要求重新核对，保持草稿；排除也覆盖历史回答继承的来源 | 对 Q19 仅增加本人可见的最小来源投影；内部追溯记录仍不直接外发，旧记录不补造证明 |
| D1：Android 系统推送候选 | 使用现有 Backend 主机、现有 Firebase 项目和 FCM；拟精确加入 `firebase_messaging: 16.7.0`，沿用当前 Core/Auth 与 Admin 14.3.0；注册类型只选 `fcm_token`；只发通用提示与受权定位信息，不在锁屏发送正文 | 需要明确批准这一依赖、注册标识交给 Google 的用途和新投递接口；不新增服务器或托管调度平台 |

F0 和 F1a 可以一起批准、分开实现。建议先接通 F0 一条完整路径，再接 F1a，
独立 QA 审查每个可运行切片。D1 的实际项目权限、注册与发送须在代码候选完成后
另核对具名账号、设备和测试窗口；此处的实现选择不授权部署或实际发送。

Delivery 的官方元数据与源码核查显示：最新 Messaging 17.0.1 要求 Core 5.x，
16.7.1 也要求升级当前 Core；16.7.0 满足本项目 Flutter/Dart/Core 版本约束。
因此选择它作为本轮兼容候选，不称其最新版本或构建已通过。当前 Admin 仍提供已标记
deprecated 的 token 发送接口；真实 provider 接受性尚需后续受控验证。
不在这次选择中顺带升级 Core/Auth 或切换 FID；若实际依赖解析需额外升级，单独报告差异。
SDK 默认自动初始化/注册保持关闭，用户明确开启前不生成本轮推送注册。
Integration 和 QA 另发现 Admin 14.3 的 `Messaging.send` 内部默认重试，不能把一次 SDK
调用当作一次外部投递。D1 因而拟保留现有 Admin 凭据接口，仅用它取得访问令牌，消息通过
Node 原生 HTTPS fetch 对固定 FCM v1 地址单次 POST，禁止重定向、自动重试和失败后换方式
重发；不修改 SDK 内部或新增依赖。取令牌结束及实际发送前须重新核对来源、同意、有效期
与取消状态。该发送细节正在纳入相同合同，不扩大上述数据用途或费用授权。

F1b（Interested/Going 与活动最新详情）暂缓接线：现有活动投影还不能证明所需的
当前状态及来源版本，不能把五分钟前的缓存当成活动未取消的证据。位置、长期画像、
根据签到/Going 自动触发跟进、跨账号设备转移、真实个人数据云传输均不包含在推荐范围。

详细且可逐项审查的 HTTP、数据字段、来源与历史依赖、原子发布、重启和撤销合同见
[Context 的 F0/F1 附录](../evidence/ai-companion-20261025/context.md#proposed-first-vertical-contract--f0-one-explicit-follow-up)
（`3ed4b3e`）与 [Delivery 合同](../evidence/ai-companion-20261025/proactive.md#concrete-resource--permission-packet-for-integration-and-li--proposed)
（含 SDK 核验的 `4a388d9`）。这些仍是提案；当前已实现的纯投影/策略测试不等于数据库事务或通知证明。

## 真实通知测试的准备范围

可审查候选完成后，推荐单个 LI 指定的既有账号、单台 LI/SHI 操作的设备，
使用合成内容，限定 30 分钟。为遵守每天一次的产品频率，最多三次发送分别是：
一次正常完整跟进，以及最多两次明确批准的后台/普通关闭运输诊断；后两次不会
再生成或保存新消息，也不冒充三次完整产品验收。另一方案是分日执行正常流程。

预估上限为 512 次文档读、64 次写、16 次删除、64 KiB 新逻辑数据加实际索引开销、
1 MiB 增量数据库流量。实际区域/费率尚未核实，USD 0.01 非模型额度只是待确认上限，
不代表已获免费配额或会产生该金额。任何实际发送或写入前须完成环境与数据清单核对。
Android 强制停止与普通关闭分开报告；不承诺绕过系统强制停止。

## 可单独选择的 Gemini 合成评测

推荐仅研究一个稳定候选 `gemini-3.8-flash`，使用 Gemini Developer API **Standard paid**。
32 个固定合成案例运行两遍，最多 64 次生成及 64 次计数调用；每次输入最多 8192 token，
思考与输出合计最多 2048 token，`thinkingLevel:low`。不传真实账号、签到、Persona、位置或历史。

申请本次 **USD 1 模型 token 支出上限**：按 10 月 25 日官方 Standard 单价计算，
64 次最大 token 估算为 USD 0.884736；税费/付款条件另核对。这不是 Cloud Billing 总账硬上限，
也不授权充值。执行前重核价格；失去授权、未知响应或预算不足立即停止，不重试或切换服务。
[官方价格](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.8-flash)

执行需要符合条款的成年操作者/地区、明确的已启用计费项目及服务端密钥。付费服务不将
请求用于改进产品，仍有安全/法律留存与跨境处理；不是零留存。应用目前尚未证明符合
提供方的用户年龄条件，因此此选择只批准开发合成研究，不批准产品接入或真实用户数据。
[官方适用条款](https://ai.google.dev/gemini-api/terms)

可审查实现已完成并经过独立反例修复：
[执行器、默认 dry、预算预留和原始证据](../../tool/ai-companion-eval/README.md#guarded-cloud-candidate-disabled-by-default)，
精确源码 `24f913d`；[独立 QA 复核](../evidence/ai-companion-20261025/qa-review-followup.md#runtime-repair-and-a-new-dispatch-counterexample)。
未满足上述条件不会产生云端调用。密钥只通过服务端环境配置，不放进聊天或仓库。
