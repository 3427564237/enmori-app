# ENMORI 下一轮功能优先级

状态：LI 已确认的产品计划。首批头像及第 1–3 项已进入 27 October 实施批次；源码验证与运行验收见[交付记录](../handoff/2026-10-27-next-features.md)。第 4–8 项也已完成本地源码实施，见[剩余功能交付](../handoff/2026-10-27-remaining-features.md)；实际设备与 Release 仍待验收。

## 来源与执行顺序

2026-10-27（Asia/Singapore），LI 要求提出无需等待队友现有交付的高价值增量，
随后确认：“ok就按这个优先级先写下来，把自定义头像所有人都能看到这个也加上。”
LI 又确认执行包含以下顺序及头像规则的完整计划。本记录落实计划中的
“先记录功能顺序与确认的产品规则，不开始实现”，不将写入文档表述为功能交付。

头像作为现有功能补全纳入首批；其余新功能按已确认的推荐顺序推进。

| 批次 | 功能 | 第一版目标 |
| --- | --- | --- |
| 首批 | 自定义头像对其他用户可见 | 所有已登录用户可查看；遵循[头像可见性决定](../decisions/2026-10-27-li-avatar-visibility.md)。 |
| 1 | 活动时间快捷筛选 | 今天、本周末、未来七天及时间排序；明确已加载范围。 |
| 2 | 签到引导卡片 | 提供可编辑的记录提示，降低开始记录的门槛；不自动保存。 |
| 3 | 签到关键词搜索 | 按日期范围搜索本人记录的文字、活动和地点名称，逐步展示结果，可停止。 |
| 4 | 个人一周回顾 | 展示记录天数、用户填写的心情与活动分布，可返回原记录；首版不用 AI。 |
| 5 | 活动地点打开地图 | 使用真实场馆地址打开地图；缺失时明确提示，不新增后台定位。 |

| 7 | 活动最近浏览 | 本次会话内快速找回看过的活动，进入时核对最新状态；不新增云端收藏体系。 |
| 8 | AI 对话定位与跳转 | 基于现有搜索跳到原消息并高亮，支持返回最新回复；不改模型或提示词。 |

## 实施边界与接口

- 优先复用现有数据、接口和组件，独立推进可行增量。此清单不代表已向队友派发任务，
  也不改写既有交付的实际状态或作者归属；共享文件仍由 LI 串行集成。
- 头像扩展现有本人专用读取能力，增加面向已登录用户的受控读取；修改权限仍只属于
  本人。实施时落实必要最小合同，并保留旧客户端兼容性和未知写入恢复。
- 系统日历等接入在对应实施包中明确必要接口；本记录不选定新依赖、数据库字段、
  迁移、服务或基础设施，也不将尚未确定的具体方案写成既成事实。
- 现有活动详情、头像保存恢复等待办与本清单分别跟踪，不能重复计为新功能已完成。

## 验收要求

- 头像按[专门决定](../decisions/2026-10-27-li-avatar-visibility.md#验收要求)验证两个不同
  账号、非好友、资料受限、旧私有照片、更新、移除及权限拒绝。
- 每项增量覆盖正常、空结果、加载失败、取消和账号切换；保留现有草稿与未知结果保护。
- 搜索、筛选及回顾不得把部分已加载数据描述为完整结果；未读完或读取失败需如实呈现。
- 头像显示、地图和日历等端到端行为需实际设备验证；源码测试、真实账号验证、手机验收
  和 Release 分别记录，不能互相替代。
- 对本次文档记录仅检查链接、顺序、规则一致性及差异格式，不运行应用构建或真实写入。
