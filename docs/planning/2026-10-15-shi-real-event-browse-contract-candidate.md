## Source validation and privacy boundary

Validation occurs in Event Infrastructure against one complete provider response and maps only the approved projection through an inner Event Port. Auth/account failures cause zero provider calls. The adapter does not select or update `active`, `published`, Interest tags or any recommendation fields.

For this narrow first increment, propose only source occurrences with status `onsale`, a confirmed future precise start, SG venue-country evidence, valid occurrence identity/title and approved HTTPS source URL. `onsale` is a conservative browse filter, not ENMORI publication state, available tickets or registration permission. Require all four uncertainty flags `dateTBA/dateTBD/timeTBA/noSpecificTime` not true. No inferred midnight/timezone/duration. Non-SG, uncertain, started, removed/cancelled/postponed, malformed or insufficient records are excluded; provider Detail absence or an ineligible Detail returns a safe unavailable result, not its stale list copy.

Proposed projection limits reuse the existing Event display boundary: title1–200 scalars, location1–200 and category1–100; reject malformed Unicode, prohibited control/bidi, markup or whitespace-only fields, preserve valid source text without truncation. A present optional field that is invalid excludes the occurrence rather than fabricating a value. Missing optional fields are omitted, not null, and explicitly labelled in UI.

Accept valid source ISO8601 timestamps with explicit Z/offset, normalize to UTC Z with at most nine fractional digits using the existing pinned time tooling, without dropping precision or assuming a timezone. Require end strictly after start when supplied; absence is omitted. Date-only, local-only, invalid/ambiguous start or malformed supplied end fails validation. The precise normalization rule is a new adapter contract candidate; the old recommendation/detail timestamp rules are not broadened by it.

Propose source URLs of length1–2048 with HTTPS, exact host `ticketmaster.sg` or `www.ticketmaster.sg`, default port443, no userinfo/fragment/control, and no embedded API key/token. Only the exact returned source URL is usable; no constructed registration URL, redirect following at Backend, arbitrary user-supplied URL or host suffix acceptance. This conservative host rule must be tested with new authorized source content before activation; the historical sanitized probe establishes only host presence, not complete URL safety.

The browse namespace never enters Friend common-Event matching or own participation state. An independent future approved mapping/producer is required; decoding a browse ID does not establish ownership, current availability, participation or ENMORI identity.

## Error contract candidate

Reuse the existing outer `ErrorEnvelope` with safe approved messages and server-generated requestId; all responses `Cache-Control:no-store`. Proposed statuses: 400 `REQUEST_INVALID`, 401 `AUTH_REQUIRED`, 403 `AUTH_FORBIDDEN`, 409 `ONBOARDING_REQUIRED`, 404 `EVENT_UNAVAILABLE` for Detail identity/absence/ineligible source, 503 `SERVICE_UNAVAILABLE` for dependency/validation/permission/timeout/quota failure. Reuse only after verifying the current normative catalogue; introduce no provider errors/messages, key-bearing URLs or new failure strings. List error cannot masquerade as zero items. Ordinary client retries are explicit new reads, not silent provider retries. The HTTP permission/consent boundary remains the existing Event read purpose, not AI optional-processing consent.

No operation logs contain occurrence/browse IDs, raw request URLs/query/key, title/body, raw provider failures or user identity. Use only Q14-allowed route template, safe status/category, latency and request correlation. Public diagnostics cannot expose the private credential filename/host configuration.
