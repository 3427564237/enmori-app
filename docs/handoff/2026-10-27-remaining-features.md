## 功能与入口

| 项目 | 行为与范围 |
| --- | --- |
| 一周回顾 | 签到历史的“回顾截至所选日期的七天”；按捕获的设备 IANA 时区逐日、逐页读取，统计有记录的日期数、原始心情/活动标签次数，未填写单列。无需 AI，不推断心理状态。支持停止/继续，未读完和失败均显示不完整；点记录走既有本人读取。 |
| 完整地址地图 | 活动详情显示来源完整地址；同一且唯一场馆必须具备街道、城市、SG 国家和六位邮编。缺字段、非法文字或多场馆时不输出地址并禁用地图，不以场馆名或坐标猜测。Android 打开地图地址搜索。 |
| 加入系统日历 | 活动详情打开 Android 原生日历编辑页，预填真实标题、开始时间、可选真实结束时间、地点及来源链接，由用户确认保存。缺结束时间不编造，并提醒核对系统默认时长。不授予日历权限，不改 Interested/Going。 |
| 最近浏览 | 活动列表右上角历史入口，最多 20 个唯一活动 ID，仅本次认证会话内存保存，可清空。同 UID 会话替换也清空。列表重新读详情，进入活动再次核对；失败不冒充空列表，五分钟过期不展示旧标题。 |
| AI 定位与跳转 | 现有搜索的上下文页新增“跳到原消息”，返回同一对话的已加载原消息并高亮；长列表逐步定位，支持回到最新已加载消息。两种聊天布局均保留草稿及选区，不发模型请求，不更改提示词。已有来源可见性、删除、待处理和未知结果保护继续生效。 |

## 接口与实现边界

- 现有 `GET /v1/events/:eventId` 增加显式 `includeVenueAddress=true`；只有请求该扩展时
  才可能返回 `venueAddress`。无查询时原响应逐字段不变，旧 `EventDetail` schema 保留。
  新客户端需要本批后端；旧服务器拒绝查询时如实显示失败，不静默降级成场馆名地图。
- 地址只来自 Ticketmaster 当前来源投影；既有 Firestore 控制数据不新增字段。
  不加数据库、索引、持久浏览历史、地图服务、插件或依赖。
- 地图与日历在 Domain 定义端口、Data 包装 MethodChannel，两个实际应用入口均组装。
  通用详情和实际参与详情页均接入；调度前核对会话、前台、当前页面及详情有效期。
- 只把 OS handoff 当作打开编辑器/地图，不当作已保存、已报名或外部应用成功结果。
  非 Android 或设备无处理应用时显示不可用，不崩溃，不新增 iOS 日历实现声明。
- 最近浏览只缓存 ID，五分钟详情有效期仍适用；一周回顾复用搜索扫描器的取消、
  游标重试及权限撤销保护，并使用独立 Provider 实例。
