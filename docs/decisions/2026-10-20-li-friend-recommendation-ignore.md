# PM 决定：持续忽略好友推荐、恢复与 Undo

## 批准规则

1. 忽略仅影响本人 Home 的 People You May Want To Know 及 See all 推荐列表。服务端保存后跨刷新、重登、正常服务重启保留，直到本人恢复。
2. 推荐页提供“已忽略的人”入口；本人可手动恢复。恢复后按当时权限、资格和既有推荐规则重新计算，不保证目标立刻出现，不强行插回旧名次。
3. 忽略不是拉黑，不阻止准确 Username 搜索或现有好友申请，不取消现有好友关系，不通知对方，也不授予新的个人资料读取权限。
4. 任一方永久删除账号时清理其关联忽略记录；暂时不可见/不符合资格时隐藏目标，保留忽略事实，不借管理列表泄露当前无权查看的身份/资料。账号删除执行器若尚未交付，明确标记该清理接缝未验证，不声称已清理。
5. **即时 Undo**：忽略成功后复用现有 SnackBar，显示“已忽略此推荐”及 `Undo` 操作，供误点后立即恢复；沿用项目既有显示时长和可操作反馈，不增加新页面、倒计时服务或新的独立 Undo 后端机制。提示消失或离开页面后仍可从“已忽略的人”恢复。

## Undo 与保存失败的衔接

- Undo 与长期恢复入口调用同一恢复操作，由服务器保存最终事实；不能只把卡片重新显示而保留服务器忽略状态。不要通过延迟持久化让忽略仅在内存生效。
- 等待忽略结果期间防重复点击；只有确认忽略成功才显示成功提示和 Undo。失败明确反馈并保留可恢复状态，不伪装成功。
- Undo 进行中防重复提交；成功后重新读取/刷新共享推荐状态。恢复失败显示失败，保留真实忽略状态和长期恢复入口；未知写入结果先核对当前服务端状态，不自动重复写。
- Undo 绑定触发它的当前账号、目标和适用版本；连续忽略不同人时，当前提示只能恢复其对应目标。账号切换/退出后旧提示与回调失效，不得恢复另一账号的设置，也不得用旧回调覆盖更新后的选择。
- 列表、已忽略管理页、恢复及 Undo 都遵守当前授权；目标已删除/变为不可见时不从本地旧卡片补回受限资料。

这些是已批准体验的最小实现与错误恢复要求，复用现有 Riverpod/Repository、身份认证、并发和安全错误规范。未指定新增 API 路径、Firestore 字段或依赖，不借此扩展通用撤销系统、通知或审计记录。
