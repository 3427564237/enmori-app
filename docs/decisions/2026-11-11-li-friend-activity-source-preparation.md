# LI — prepare the existing Event source for Friend Activity reads

Date: 11 November 2026 (Asia/Singapore). Authority: LI / PM's current immediate-demo task; implementation detail confirmed in its delegated repair.

LI asked whether a friend can see new or updated Check-ins and Interested actions in Friend Activity, following the [immediate-demo instruction](2026-11-11-li-immediate-demo.md) to repair existing functionality and allow longer slow-request waits. Investigation found that the ordinary Friend Activity path consumed the current Event projection without the public-source preparation already wired for recommendations. A cold, expired or pending source could therefore reject All/Event Activity even when its source could be refreshed normally.

For All, Interested and Going reads, after authenticated viewer/optional-processing authorization, prepare the existing bounded public Event snapshot outside Firestore transactions. Then freshly read the viewer identity binding, friendship, eligibility, profile and record/participation visibility, consent and current sources in the normal transaction. Revalidate the prepared generation before returning. The Check-in-only category does not prepare or depend on Events. Retain the 90-second provider and 110-second aggregate snapshot budgets; give All/Event Activity GETs 120 seconds at the client. Ordinary reads, Check-in-only Activity and writes retain their existing deadlines. No retry, polling or background provider acquisition is introduced.

Activity and friend recommendations receive the same composition-owned preparation callback and share the same snapshot cache and pending read. Concurrent Home readers join that work; Activity must not trigger a separate page-zero refresh that invalidates the recommendation's generation.

This supersedes only the composition limitation in the [FA2 contract](../../api/friend-activity-display-contract.md) that an ordinary Activity read cannot first prepare the existing public source. It does not remove that contract's current-source checks: missing titles, failed preparation, expired/replaced source generations and revoked authority remain unavailable or omitted according to their existing meaning. Preparation runs before personal-source reads; no provider network I/O occurs inside transactions, archived title is served, or new API, data field, dependency or source is added.

The [20 October display decision](2026-10-20-li-event-batches-friends-activity.md), [Q03 ranking](2026-09-01-deterministic-v1-recommendation-formulas.md) and selected-at semantics remain unchanged. Activity requires accepted friendship; only the inclusive previous seven days qualify. Check-in edits update the saved display while preserving its original creation time; they do not create a new activity. Interested/Going transitions use actual selection time; cancellation removes the selection and Ignore/Restore does not advance it. Home still contains at most two ranked activities, and the full list retains the same order and category filters. This change does not claim dual-phone acceptance.
