# 交互状态与模块交接

2026-10-25 · Product / UX · Proposed。使用 [选择材料](product-choices.md) 的来源顺序；此文不定义生产 DTO 或存储。

## 入口与话题

C 推荐候选先以现有 Conversation 作为上下文和删除边界。连续的是主入口；不是把全部历史拼成一个请求，也不是永久记忆。
首次没有历史时显示可选处理说明和空输入；当前同意/账号无法核实时不假装是首次空账号。
日常返回应优先恢复已有未确定操作，其次是可读会话与阅读位置；具体恢复记录需要 P6 决定。

历史仍可发现，搜索明确限定当前会话已加载的可用消息。跨会话全文搜索、服务器话题标题、分段实体、跨设备阅读点均不是现有合同。
新话题保留单份当前草稿供编辑，但不自动复制已选旧来源。打开另一会话（包括通知、主动回复）前，未发送草稿必须确认保留编辑或放弃。
原型修订后只用一份当前草稿，不暗示多个话题各自持久缓存。草稿不向服务器保存。

## 状态与交互

| 状态 | 可见内容及可用动作 | 保留 / 禁止 |
| --- | --- | --- |
| 首次进入 | 查看本地/云端及范围 → 显式演示选择 → 开始；也能返回 Home | 不默认批准新数据用途；真实设置读取失败与拒绝同意要分开 |
| 可发送 | 输入、参考来源、处理位置；明确 Send | 2400 Unicode scalar 上限；emoji 不按 UTF-16 单元翻倍；不自动发送 |
| 等待 | “正在准备回复”；取消等待 | 非 streaming；保留草稿、旧记录；停用再次发送与话题切换 |
| 取消后结果未知 | “可能已保存”；核对原操作；直接离开不重试 | 取消不等于回滚，不增加重发按钮；返回仍受同一未知结果保护 |
| 已确认未发送 | 本地服务失败提示；保留草稿；用户可显式再试 | 只有确定 no-effect 才允许该动作；不会自动回退云端 |
| 来源更新 | 显示需核对，发送禁用；查看当前版本再采用或明确排除 | 不静默使用旧内容，不静默删掉来源后发送 |
| 来源核对失败 | 明确未知而非空/不存在；可再次核对或明确排除 | 不显示旧正文，不把 unknown 改成删除/成功 |
| 来源删除/许可撤回 | 相关消息内容不可用；旧通知打开到状态页 | 不重建正文/旧 ID，不推断仍可回复，不把旧摘要当事实 |
| 迟到过期/活动取消 | 旧联系不可继续，返回当前主入口 | 不补发积压、不重开活动提醒；Interested 不触发 Going 提醒 |
| 查找失败 | 保留查询、已得结果和早页游标 | 不把失败当空结果；不扩大查询用途或持久化搜索词 |
| 删除确认 | 整段当前会话和所有消息，无恢复；其他业务记录保留 | 不是单条消息删除；不是新话题；新功能不能延长 Q14 保留期 |
| 删除未知 | 内容隐藏，核对原操作 | 不恢复消息，不用“新对话”绕过未知状态 |

## 主动消息纵向流程

推荐先做“用户明确请求的一次跟进”。原型从当前话题进入“约个稍后跟进”，显示事项、日期时间、IANA 时区、一次性范围和显式确认。
确认只开启该合成类别，不自动开启系统推送。真实请求录入、授权和确认版本由 Proactive 合同决定。
保存的消息身份是真正 assistant proactive；不制造 user message；模型不决定是否有触发权。

主入口未读卡 → 打开原消息（此时才视为阅读）→ 原因 → 受信来源 → 回复；输入框始终提示原话题及被回复消息时间。
原型等待/未知时把待发原文留在只读输入框以便检查；这只是演示摆放位置。生产 App 已 admitted 的 Send 可以清空 composer，并在本地 outgoing 区保留原文，不要求把已发送文本恢复成可重发草稿。

这里的定位是固定 fixture 映射，不是生产能力。真实通知必须通过受权 resolver 校验账号、conversation/message 归属、当前许可和可用性，
再取得可导航的 anchor；现有 controller 仅接受已授权列表中的会话、查找也只定位已加载消息。不能凭拼接 route query 宣称已具备通知定位。

设置候选与 Proactive `48ac991b8978d1d7ad47ee21e9a5b7d52c3f5221` 对齐：
总开关 off；明确跟进先选，Going/签到后轻问另选；滚动 24h 上限 1（比较项 2）、冷却 8h；22:00–08:00；未知时区暂停；锁屏只通用消息或不显示。
**这些是演示值，未获 LI 确认，不能写成生产默认。** 暂停后恢复重新核对，关闭取消未投递项且停止新生成；已保存会话保留。
已交给平台的通知能否移除依赖平台，不承诺全部追回。本地模型也不代表推送服务是本地处理。

| 投递情形 | 本原型能说明的设计 | 仍需实际证据 |
| --- | --- | --- |
| App 前台 | 未读卡、原因、来源、阅读/回复及失效页面 | 后端触发、真正保存、App 接收、去重、read acknowledgement |
| App 后台 | 通用锁屏内容和点击后的期望路径 | 已批准投递机制、系统权限、真实设备、正确目标读取 |
| App 普通关闭 / 被系统终止 | 仅展示待验证说明 | 实际支持的平台机制、离线/迟到/TTL、通知定位；不得以前台计时器证明 |
| 强制停止 / 权限撤回 / 无网络 | 有明确不可保证边界 | 分状态测试；不把“关闭”混作一个保证，不无限补发 |

## 本次参考与处理位置

本次参考可查看、暂时排除、主动附加。日期和时区靠近来源；历史心情始终注明“记录时”，活动明确 Interested / Going，均不等于已参加。
本次排除须同时移除该记录及依赖它的自动历史引用，不能通过历史再次引入同一来源。它不删除原记录，也不抹掉用户主动写入当前消息的内容，不表示永久遗忘或撤回所有用途。成功模拟发送后重置本次选择，失败/未知保留；新话题不继承。
Context 候选 `8ce74a8` 在已选历史依赖被排除记录时返回 `invalid_selection`，没有 modelContext；App 保留草稿和选择，提示审阅关联完整历史 pair，明确将其一同排除后重新 prepare。不能把该状态当成功、静默剥离 provenance 后继续正文，或要求后端自动净化请求。
原型只演示控制与说明，未实现真实历史投影/prepare。

首流建议将本次参考作为可信的 request-level sidecar 列表，继续用纯文本显示模型正文。来源存在且可定位不证明某句生成内容被来源支持，也不需要先增加 Markdown citation parser。

当前 Q19 provenance 是 Backend-only。必须单独批准 UI-safe 最小投影与可信导航，再接入 App；模型只能引用后端批准的显示映射，不能提供有权限效力的 ID / URL。
签名前/发送前需要 owner、purpose、version、consent、有效时间及来源可用性重核；来源显示失败不能改成“当前没有记录”。
UI 层只请求选择，不授予读取或模型使用权限。Q17 当前禁止用户位置（包括 Approx Location）进入 Qwen；原型没有 GPS/位置附加选项。
Event 的公开场所与用户当前/历史位置是不同数据来源；前者进入模型仍需本轮相应用途合同，不能由卡片展示自动批准。

“本地服务”明确是配置的本地模型服务且经 ENMORI 后端，不声称手机端/离线。云端需单独说明服务商、处理条件、数据范围、费用和可撤回边界。
原型云端复选框仅切换页面状态，不能当真实同意；失败不自动转云端。

## 交接接口需求与未决项

- Context：最小可展示来源、版本/时间/可用性及可信目标；候选选择/排除的请求生命周期；重核失败的稳定状态。现有 provenance 不直接导出。
- Proactive：明确触发要求、当前许可、原话题/消息归属、未读与已读、待发撤回/过期/去重、后台能力事实。R-ANCHOR / R-SPLIT / R-EXTEND 保留期比较须总控汇总；不自选任何锚点规则。
- Runtime：本地/云端可用性、已选择处理位置、范围说明、已知失败/结果未知分类。真实云端服务、预算和数据范围另选。
- App：source card / pending / unknown / unusable / picker 只是待接组件状态；先继续已确认行为的文字阅读、草稿、返回和无障碍修复。
- Integration：统一新合同、共享路由/主题/组合及 LI 的一次具体选择。原型不新增 production API、数据库、依赖或后台服务。
- QA：独立读精确源码和关键反例；本原型只算 D-layer 设计/浏览器证据。模型语义、服务、APK、真机、后台投递、UAT 分开验证。
