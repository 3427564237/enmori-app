# ENMORI Scrum Planning

Read `references/team-policy.md` on every invocation. Select the Refine, Plan, Rebalance, or Close mode, then read that section in `references/workflows.md` and the matching format in `references/output-formats.md`.

Before planning affected product work, read `AGENTS.md`, `docs/PROJECT_CONTEXT.md`, `docs/SOURCE_MAP.md`, and `docs/OPEN_QUESTIONS.md` when present. Preserve their evidence hierarchy and decision status. Report conflicts instead of resolving them silently, and block only the affected scope.

Apply PM direct assignment and all fixed team, capacity, estimation, WIP, reviewer, testing, completion, and iOS evidence rules from the policy. Do not approve requirements.

Show a complete, human-reviewable preview before applying any change. Request explicit PM approval for the exact current preview immediately before writing to GitHub or Notion. If approval is absent or the required connector is unavailable, perform no external write. A changed preview requires new approval.

Clearly distinguish observed repository or external state from proposals and unverified outcomes. Do not claim a preview was applied without observing the resulting state.

This Skill plans and governs work; it must not implement the planned product work.
