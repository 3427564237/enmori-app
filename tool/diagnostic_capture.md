## What is wired

The live `controlled_phone_service.mjs --live-existing-host` entry now requires capture health **before starting emulators**. Its execute child constructs `createHostDiagnostics` before model preflight, then injects the collector into the existing transport/compiler/service. No config switch can suppress capture in this live entry. Ordinary app bootstrap is unchanged.

The client invokes only `/usr/bin/sudo -n -- /usr/local/sbin/enmori-diagnostic-capture append|health`, with a fixed environment, 2-second deadline, bounded output and no shell. The helper is a root-owned installed snapshot, invoked by an isolated Python interpreter. Backend operator has exactly append/read/health commands, no arbitrary Python, path, UID, cleanup, reset, or environment selection. The store/config/source live outside the disposable runtime profile; the operator cannot read or copy raw files. Root remains the trusted host administrator, not the ordinary Backend reader role.

The helper revalidates the Q14 metadata schema, preserves original server `loggedAt`, pins root-owned directory ancestors using descriptor-relative operations and no-follow opens, verifies ownership/mode/link count, and serializes operations on the same pinned lock descriptor. Lock contention alone may wait up to 0.2 seconds for ordinary commands or 5 seconds for cleanup, measured monotonically; exhaustion and other errors refuse without entering or replaying the operation body. The original 2-second/60-second watchdogs remain unchanged. This prevents a reproduced collision risk; it does not establish the cause of the actual 19 October cleanup failure or clear an existing failure. Reader checks expiry at each emission, at exactly 30 days; there is no export/import or renewal command. An authorized human must not redirect/retain reader output as an unmanaged copy or backup. This implementation cannot revoke information already viewed or copied outside its access boundary; such copies are outside the approved workflow, not an alternative retention mechanism.

Root `cleanup` persists intent before scanning/deleting and acknowledges only after directory fsync. It removes only validated owned expired records. A failed/unknown write/delete, interrupted cleanup, unsafe file, wall-clock rollback, changed boot timestamp, stale sweep (>65 minutes), inactive timer or failed system unit closes capture. The private state file stores scheduler control timestamps/flags only; these are not extra emitted diagnostic-log fields. Missed deadline (day31) is preserved even when catch-up deletes the file. Failure reasons accumulate; there is no automatic reset or silent new store.

Collector health refreshes through the installed helper; a failed capture latches in the current process. Prepare/execute refuse new work. The adapter checks capture immediately before physical generation dispatch. Failure **after** dispatch never changes matching-done/unknown-settlement semantics or authorizes another invocation. No operation IDs, account IDs, body, prompt, output, endpoint, token, private path or raw exception is emitted.

Root, unrestricted sudo, docker/lxd/disk or equivalent raw-root access does not demonstrate the intended reader boundary. 3. As host root, verify that the proposed dedicated store is new and outside runtime/session/config storage and backups. This installer's bounded location is a new single leaf under `/var/lib/`; its exact name remains private. Existing files/directories are refused, never overwritten. 4. Privately prepare a root-owned 0600 JSON input with exactly `operator`, `store`, `helperSha256`. 5. After the applicable new-source review/evidence gates, LI may execute the reviewed installer as host root. From an already authorized root shell, with `$CAPTURE_INSTALL_JSON` naming that private input:
